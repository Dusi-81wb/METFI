# METFI Architecture Decision Records (ADRs)

This document tracks all formal architectural and technical decisions made for the METFI project. Any deviation from the frozen architecture requires an explicit ADR entry with documented rationale.

---

## ADR-001: Deterministic Truth Authority
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** Financial reconciliation requires absolute mathematical precision and auditability. LLMs are non-deterministic and susceptible to hallucinations and arithmetic errors.
- **Decision:** Deterministic financial rules own canonical financial truth. Normalization, amount comparison, currency validation, date skews, duplicate detection, and policy gating are executed solely by deterministic Python code.
- **Consequences:** AI reasoning cannot alter ground truth, mutate ledger balances, or bypass mathematical constraints.

---

## ADR-002: Bounded AI Investigation & Structured Output
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** While deterministic code enforces rules, AI is uniquely capable of analyzing unstructured metadata, explaining subtle discrepancy patterns, and suggesting resolutions.
- **Decision:** AI agents operate in a strictly bounded capacity. They output structured, Pydantic-validated JSON containing: exception classification, plain-English explanation, field-level evidence citations, and a bounded recommendation (`AUTO_RECONCILE`, `REVIEW_REQUIRED`, `UNRESOLVED`).
- **Consequences:** All AI outputs are strongly typed and verifiable before consumption by downstream policy engines.

---

## ADR-003: Hidden Ground Truth Separation
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** To ensure uncompromised evaluation integrity, benchmark evaluations must test actual reconciliation capabilities without data leakage.
- **Decision:** Ground truth labels and corruption manifests generated by synthetic data tooling are isolated in `data/ground_truth/` and are strictly inaccessible to the ingestion, reconciliation, and AI inference layers.
- **Consequences:** Benchmark scores represent genuine zero-leakage system accuracy.

---

## ADR-004: Reproducible Benchmarks via Deterministic Seeds
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** Hackathon judges and peer auditors must be able to reproduce exact benchmark datasets and metric outputs across distinct environments.
- **Decision:** Synthetic dataset generators use explicit random seeds (`seed=42` for 500-record Dev set, `seed=1337` for 5,000-record Stress set). Datasets and corresponding evaluation reports are versioned.
- **Consequences:** Any evaluator running the benchmark commands receives identical results.

---

## ADR-005: Model Provider Abstraction Layer
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** Different deployment environments and evaluation scenarios may use Gemini, OpenAI, Claude, or local Nemotron/Ollama models.
- **Decision:** All AI calls are mediated through an abstract `LLMProvider` interface in `backend/app/intelligence/`. Domain and reconciliation code depends solely on this interface, not on specific SDKs.
- **Consequences:** Models can be swapped via configuration without touching business logic.

---

## ADR-006: Small Focused Agent Surface vs. Complex Swarms
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** Unnecessary multi-agent orchestration frameworks (swarms, autogen graphs with dozens of agents) introduce high latency, non-deterministic failure modes, and debugging opacity.
- **Decision:** METFI uses a minimal, highly cohesive agent topology: an **Investigator**, a **Resolver**, and a **Verifier**, coordinated deterministically within the service pipeline.
- **Consequences:** High processing throughput, predictable latency, lower token cost, and easy debugging.

---

## ADR-007: Explicit Architecture Governance
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** Preventing architecture drift during multi-phase autonomous implementation.
- **Decision:** Core technology decisions (FastAPI, Next.js, PostgreSQL, Polars, Pydantic, Pytest, Docker) are frozen. No architectural modifications or external dependencies may be added without documented justification in this ADR log.
- **Consequences:** High architectural stability and consistency across phases.

---

## ADR-008: Phase 0 Technology & Scaffolding Baseline
- **Status:** ACCEPTED
- **Date:** 2026-08-25
- **Context:** Phase 0 requires establishing a clean, repeatable, testable development and deployment environment.
- **Decision:** Scaffold the repository as a Modular Monolith with:
  - Backend: FastAPI with Pydantic v2, Python 3.12+, Uvicorn, SQLAlchemy 2.x, PostgreSQL 16.
  - Frontend: Next.js 14+ (App Router), TypeScript, Tailwind CSS, Lucide icons.
  - Packaging: `pyproject.toml` (managed via `uv`), `package.json` (npm).
  - Containerization: Docker multi-stage builds and Docker Compose orchestration.
- **Consequences:** Rapid local development, standardized testing, and containerized deployment parity.
